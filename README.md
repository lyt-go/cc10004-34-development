# 数据产品运营与归因分析平台

面向数据产品运营、渠道归因、用户行为分析、ROI评估、转化优化与数据应用监控的数据分析工程平台。

这是一个**纯前端**管理平台：React + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 React + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 投放命中沙盘

`/hit-sandbox` 是面向投放排期的命中沙盘：先选画像定义，再圈定分流方案，页面同时展开分层人群、
白名单用户、各层分流比例和最终命中结果。实现分三层：

- `frontend/src/data/hit-sandbox.ts`：画像分层模型、方案对接关系与纯试算引擎（重叠去重、按比例分名额、
  白名单优先占名额），不读写存储。
- `frontend/src/data/hit-store.ts`：批次台账与沙盘草稿的 localStorage 存取；批次只追加，复核只改状态。
- `frontend/src/api/hit-service.ts`：页面唯一入口，负责选画像 / 选方案、试算、正式提交、冲突判定、
  复核和画像换版重新排队。

约定与边界：

- 试算预览只读：改比例、改名单、反复预览都不写批次、不占实验名额；草稿按「画像::方案」分开保存，
  刷新或返回后仍在。
- 正式提交才生成不可变批次：`HIT-YYYYMMDD-NNN`，画像与方案字段、比例、白名单、命中结果全部写进
  批次快照；之后模块里的记录再改，旧批次查看时仍是原样。
- 同一方案在同一画像版本下以首个完整批次号为准：第二路提交提示冲突并指向已有批次；重复点击同一请求
  会回放原批次，不重复占名额。
- 画像状态分三档：已发布可直接提交；评审中可试算但暂不能提交；作废只保留定义与历史批次供查看。
  草稿状态不展开试算。分流方案同理（未生效可试算、已下线只看历史）。
- 边界层级：相邻区间含边界时按「高阶优先」只落一层，低阶层扣除重叠人数；白名单同步去重。
  空白名单表示全部按比例分配；不在本方案分层内的白名单用户不计入命中，预览中单独列出。
- 画像换版：在批次详情里改分层人数 / 区间并填新版本号，只让发生变化的分层重新排队，其余分层沿用
  上一批次的命中，生成「待复核」批次；旧批次不动。
- 预览页会对照展示 PROF-0003 的统计维度、聚合指标、分层区间、更新周期、覆盖用户量，以及
  ABGR-0003 的分流类型、分流比例、分组标识、白名单用户、生效页面。

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.tsx`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`（命中沙盘走 `hit-service.ts`）。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `data-product-ops:entries` 这一项，或调用 `resetModule(模块)`。
  命中沙盘另有 `data-product-ops:hit-batches`（批次）与 `data-product-ops:hit-sandbox-drafts`（草稿）两项。
